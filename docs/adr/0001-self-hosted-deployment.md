# 使用独立的云服务器部署方案

当前实施按用户最新要求先交付最小 demo：只打通 Bun + SQLite、七牛前端直传直下、前端 zip 处理及两种部署入口。提供 SQLite 手动快照命令；每日备份调度、快照上传七牛、7 天保留、应用产物回退自动化作为后续目标，本轮不实现。不增加自动重试、定时清理、上传恢复状态机或服务端 zip 处理。

当前实现与 Cloudflare Workers、D1、R2 及 Wrangler 部署流程耦合。为使完整业务能够在没有 Cloudflare 账号的情况下运行，管理端、API、数据库和 Skill 包存储将解除对 Cloudflare 的强制依赖，不再维护 Workers 部署路线；未来可按需独立接入 CDN。

首期以单台 Linux 云服务器部署，接受维护或故障期间短暂不可用，优先服务中国大陆用户。选择这一部署边界以控制首期维护成本，同时接受单机故障会影响整个服务的取舍。

按全新安装设计，不考虑旧数据迁移。首期按小规模试运营、用户规模 100 以内规划，不将该人数直接视为并发请求数或容量验证结果。

同时支持 Docker Compose 整体部署，以及不使用 Docker 的原生部署：前端静态文件独立发布，API 直接在服务器运行，由 systemd 管理进程。两种方式使用同一套应用代码与配置。

API 保留 Elysia，使用 Bun 运行，以本地 SQLite 替代 D1。SQLite 文件位于服务器的持久化目录；Compose 挂载该目录，原生部署通过配置指定目录。

首期将 Skill zip 保存到七牛云私有对象存储，作为正式文件的主存储。服务器数据库保存文件 ID 与 Skill 版本等业务关联，下载继续要求用户鉴权。

经七牛官方文档核实，上传策略的 `fsizeLimit` 可以在七牛侧强制限制单文件大小，超限返回 HTTP 413。因此按用户确认的条件采用前端直传：管理员向 API 申请上传凭证，API 签发限定目标文件 Key、只允许新增且短期有效的凭证，凭证内设置压缩包最大 10 MB；前端持凭证上传至七牛，不接触服务端 Secret Key。

Skill zip 的压缩、解压、内容校验和 canonical hash 计算由管理端前端完成，上传与下载的文件数据直接在前端和七牛之间传输。API 不下载 zip 进行重复内容校验，不解压或重新打包 Skill 文件，也不重新计算其内容哈希；本方案由已鉴权的管理员前端提交内容哈希和清单快照，服务端保存这些业务数据。

点击发布时，前端固定本次文件和清单快照，使用同一快照完成内容校验、canonical hash 计算、压缩和元数据提交；发布期间暂时禁用编辑，完成或失败后恢复。

上传成功后，前端请求发布确认。API 仍负责管理员权限、元数据格式、上传与 Skill 及目标 Key 的关联、对象存在性、重复版本及版本数量限制等业务检查，发布成功后版本才出现在列表中。发布按正常请求流程设计，失败时提示，不额外扩展复杂的自动重试及异常恢复机制。这些业务检查不读取或校验 zip 内容。

文件清理由前端请求清理接口触发，后端鉴权、核对记录及文件引用后执行七牛删除；仍被正式版本引用的文件不得由清理接口删除。未完成发布的上传通过这一流程清理，已发布对象不能被上传凭证覆盖。

下载时，API 按文件 ID 验证用户权限和版本引用，生成七牛私有文件的短期签名下载 URL，前端或客户端直接从七牛下载文件。七牛密钥仅保留在服务端；管理端浏览器直连七牛所需的 CORS 与 HTTPS 配置在部署时提供。

10 MB 仅限制单个 zip 压缩包，不新增解压后的总大小上限及此前建议的 1,000 个文件限制。压缩和解压在前端执行，不引入服务端解压校验进程。

应用部署采用手动触发，部署前生成 SQLite 快照，并保留上一版应用产物供回退；应用回退与数据库恢复分别处理。

域名、访问路径和 HTTPS 入口方案按用户要求留待后续确定。每日仅备份 SQLite 一致快照，上传到独立的七牛私有备份空间，保留最近 7 天并提供恢复步骤；不备份七牛中的 Skill zip，也不再要求数据库与对象文件组成同一备份批次。快照使用 SQLite 支持的一致备份方式生成，不直接复制正在写入的数据库主文件；无须为复制 Skill 文件而暂停发布、删除或清理。

备份的过期清理规则仅应用于备份空间。恢复 SQLite 不会恢复七牛中已删除的 Skill zip，数据库快照中的文件引用需以七牛实际保留的对象为准。

本记录确认新的部署与职责边界，尚未实施迁移。本 ADR 覆盖原设计中的 Cloudflare 部署目标、服务端 Skill 内容校验及文件中转职责；原设计中的账号权限、游戏与 Skill 关联、版本规则和 canonical hash 算法保持其业务约定。现有代码、设计和部署说明仍需在后续实施时按本方案更新。域名与 HTTPS 入口保留为后续部署决策。
